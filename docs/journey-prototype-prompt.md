# 旅程轻量交互：OpenDesign 提示词

日期：2026-10-28。状态：首版原型已完成两轮只读评审，用户要求提供修正提示词，见文末；未授权实施应用改版。分析与评审依据见 [交互反思](journey-interaction-review.md)。本轮仅记录和交付提示词，未操作原型工程。

```text
请在当前「迹屿 Travel Atlas」项目中，制作一版“旅程”板块的交互改版原型。延续现有暖纸白、森林绿、线性图标和底部四个入口，保留首页和新版照片回忆。本轮重点验证真实规划流程是否顺手，提供可以连续操作的预览。

核心顺序：先留下想去的地方，再安排到哪天，最后按需补细节。日常操作不接触经纬度、坐标系、GPX 或逐段路径资产。

一、旅程列表
保留右上角加号，用深森林绿提升辨识度，点击范围至少 44px。移除底部常驻“新建旅程”，已有旅程时避免重复的新建入口。列表以旅程内容为主，不增加大面积介绍、统计或功能卡。保留计划中／已完成筛选，归档等次要操作按需出现。

二、新建只需要一个起点
点击加号打开轻量弹层，仅一个主要输入：“想去哪里，或给这次旅行起个名字”。可以输入“武汉”选择城市建议，也可以直接用“国庆慢慢走”这样的名称开始。城市选择后可自动生成“武汉之行”，名称以后能改。日期和总天数不阻止创建，不预先生成三天空白表单，不要求填写出发地。
创建后直接进入旅程安排。新建后立刻能在旅程更多菜单找到“删除旅程”，误建的空旅程可以确认删除并返回列表。

三、旅程详情只有一个主要安排空间
顶部简洁显示可修改的名称、日期状态和更多菜单，日期未定也正常。核心内容是“待安排”和按天分组的地点；待安排属于这次旅程，不另建一套收藏功能。初次创建只显示待安排，需要时再增加第 1 天、第 2 天。日期确定后统一对应，不逐天填日期、主题、地区和住宿。
手机优先展示地点清单，地图按需切换；桌面可左清单、右地图。切换保持当前天、选中地点和滚动上下文。较多天数用紧凑可横滑的导航，不用一长串大型空白卡占据空间。

四、添加地点以搜索为主，支持连续加入
从待安排或某一天点击添加，打开同一个搜索面板，明确当前加入位置。输入地点名称，候选显示名称、所在地区／地址及小地图预览，能分辨同名地点；城市范围可切换，支持跨城旅行，不强迫重新新建旅程。
选中结果即可加入当前分组，自动带入名称、地址和位置，不再弹出六七个输入框。加入后在结果上显示“已加入”，面板保持打开，搜索输入仍可使用，能继续添加下一个地点；完成时一次返回安排。不要同一地点每点一次就重复加入当前分组。
搜索不到时，提供“先记下这个名字”，标记位置待补，仍能安排到某天。
地图微调是次要入口：先搜索或找到附近已知地点，再移动地图中心标记确认位置。日常界面不出现经纬度输入，也不要求用户在全国地图上直接点准目标。

五、地点先能用，细节随后补
地点行默认只展示名称和必要的地址／短备注；点开后才补预约时间、备注、住宿等，不逐项填写才能添加。不要在每一行常驻编辑、移动、删除、交通等一排按钮。
交通放在相邻地点之间按需设置，允许设当天默认方式并改个别路段，不要求每次添加地点都选一次。地图用于查看地点分布和安排顺序；若展示连线，标注规划示意，不声称真实徒步轨迹或已验证导航路线。本轮不展开专业算路、轨迹导入或 AI 规划界面。

六、整理必须能批量进行
支持当天调整顺序和跨天移动。手机拖动有明确手柄，不干扰正常滚动，同时提供不依赖拖动的“移到某天”。进入选择状态后，可一次选多个地点统一移到待安排或某一天，也能批量移除。
删除一天时提供“地点移回待安排”或“一并移除当天地点”，不用先手工清空。普通移除用简短反馈并提供撤销，不每次都打断确认。旅程删除保留明确确认，与归档分开。
原型用本地状态保留操作和刷新后的安排，避免“确认添加后还要保存整份行程”的双重保存。展示简洁保存反馈和一个失败可重试状态；设计说明注明这是本地原型演示，不能声称实际写入服务器。

七、回来补记保持轻量
从旅程更多菜单进入“补记这次出行”，复用已有地点，让人勾选真正去过的地方、补临时地点，确认后才形成到访；不默认把所有计划点标成去过。不要求写日记，照片为可选补充。本轮只演示简洁入口和勾选确认，不增加另一套完整的行程编辑器。
删除已有内容的旅程时说明涉及的安排、到访和分享，不默默删除独立相册照片；演示照片保留、旅程关联解除的状态，具体业务删除规则仍需后续确认。

八、用同一组数据跑通完整流程
准备“武汉两天慢游”：黄鹤楼、昙华林、江汉路、湖北省博物馆、东湖等示例地点。请注意地点的真实地理分布，不把明显跨区域的地点随意推荐为最佳顺路方案。
实际演示：
1. 日期未定新建 → 连续搜索加入至少 4 个地点 → 留在待安排。
2. 增加两天 → 多选分配地点 → 调整顺序 → 切地图查看 → 返回保持上下文。
3. 选择同名地点、搜索无结果后保存名称、搜索后微调位置。
4. 移除地点并撤销；删除一天并保留地点；删除误建旅程。
5. 补记时只勾选部分地点，不全部自动点亮。
另提供七天／较多地点状态验证批量整理，避免为演示而扩张常驻功能。

九、预览与交付
这些状态尽量复用同一个工作区、搜索面板和详情弹层，保证返回路径连贯，不做大量互不相连的静态页面。
检查 390px、320px、桌面和键盘弹出后的布局；重点查看搜索结果可滚动、主要操作可达、底部导航不遮内容、弹层不会相互叠加、七天导航和长名称不会溢出。
原型使用隔离示例数据，搜索和地图可本地模拟；不请求生产 API、不读取真实账号、不覆盖原有回忆数据。示例地图位置尽量合理，不把模拟搜索或路径说成真实服务。保留旧旅程原型以便比较，把新版加入预览目录，更新设计说明，注明演示范围。
完成后实际预览并截图，做两轮自审：先检查完整主流程，再检查窄屏、键盘、取消／返回／撤销和刷新恢复。交付可操作预览及简短改动说明。
```


## 两轮评审后的定向修正提示词

用户已要求提供本轮提示词；范围为原型修正，不代表批准应用迁移或真实业务数据操作。

```text
请基于刚更新的「迹屿 Travel Atlas」旅程工作区，完成一轮针对性修正。保留轻量新建、连续搜索添加、待安排／分天、批量整理及补记的整体结构，延续现有配色和图标。本轮聚焦以下三点。

一、批量移动保留原来的先后顺序
目前跨天多选后移回待安排，会把不同天之间的顺序颠倒。
请统一按原行程中的天数顺序、每天内部的地点顺序收集选中地点，再追加到目标分组。排序不受勾选先后影响，目标分组原有地点保持原位；已在目标分组的选中地点保持原位，不重复加入。
例如：待安排已有江汉路，第 1 天有黄鹤楼、昙华林，第 2 天有湖北省博物馆、东湖。选中黄鹤楼和湖北省博物馆后移回待安排，结果应是“江汉路 → 黄鹤楼 → 湖北省博物馆”。反过来勾选，也应得到相同顺序。
同时复查单天多选、跨天多选、单地点移动、批量移除后撤销，确保名称、位置、备注都保留，撤销能恢复原分组与顺序。

二、操作反馈轻量，并避开主要内容
目前“已移到待安排”等成功提示较高、停留约 9 秒，切到地图后会盖住底部地点摘要。
普通成功反馈改为紧凑样式，约 2～3 秒消退，优先使用页面已有的状态区域。需要撤销的操作保留清晰可点击的入口和足够操作时间，可采用与内容不重叠的紧凑区域。
请实际检查提示出现时，地图地点摘要、搜索结果、添加地点、批量操作、底部导航都能看见并点击。切换清单／地图时及时整理上一操作的普通提示，避免持续覆盖下一视图。保存失败和重试保持明确，不能跟随普通成功提示自动消失。

三、地图提供可辨认的地理参照
当前主地图只有行政区轮廓与编号点；上海中山公园的微调画面几乎是纯底色，无法判断该往哪里移动。
请让旅程地图和搜索后的微调地图具有道路、地名、水域或公园轮廓等必要参照。优先复用原型已有且可用的城市街道底图资源；如没有真实地图服务，使用经过位置核对的本地道路参考图，注明“位置示意”。只演示参考能力，不宣称精准定位或真实导航。
搜索选中地点后，地图应进入该地点所在城市及附近区域，清楚标出当前地点与周边参照。武汉和上海等跨城结果均应适配相应城市，不能沿用另一城市或全国行政区底图。微调时保留固定中心标记与可移动地图，确认后回到原搜索上下文，已加入地点和输入内容都保留。
主地图继续用于观察地点分布、先后和远近；示意连线保留规划示意标识。检查编号点、地名和选中摘要之间的遮挡，控制标注密度，不给每个点同时展开大卡片。

验证与交付
保留当前新版原型供对照，更新修正版预览入口及设计说明。示例数据使用独立本地存储，保留首页和照片回忆，不请求生产业务 API，不操作真实账号、行程或照片，也不把密钥写入页面。
请实际操作并截图验证：
1. 从不同天、以不同勾选顺序多选移动，目标次序一致。
2. 移除多个地点后撤销，恢复原分组与位置。
3. 移动后立即切地图，地点摘要和操作仍可见、可点。
4. 武汉地点及上海中山公园分别搜索、查看地图、微调、返回，地理参照与城市一致。
5. 320px、390px、桌面及缩短视区下，提示、摘要、弹层、导航互不遮挡，搜索仍可连续添加。
完成两轮自审：第一轮检查上述修正，第二轮回归新建、连续添加、分天整理、刷新恢复、补记和删除。交付可操作预览与简短改动说明，并说明地图哪些是真实能力、哪些是本地示意。
```
