## 城市卡片如何适配现有数据

建议示例结构：照片 → 城市名 → 最近记录日期 → 旅程／回忆数量。展开后可按年份分组，同一年内优先按记录时间排序；窄屏优先两列，空间不足时改为单列，长地名不能挤压日期。

汇总数量和首末日期应由服务端按同一筛选聚合，不用当前分页的长度或最早一条推算全部历史。

现有城市详情中的日记是“相关旅程的日记”，可能包含跨城内容，不能直接断言其中任意照片拍于该城市。城市封面优先用户指定、或已经明确关联该城的照片；未核实归属时用原有暖色占位与地名，或标明为相关旅程封面，不把它自动包装成该城实拍。缺日期归入待补充，不用创建时间替代出行日期。

在历史记录不完整的情况下，用“首次记录”比断言人生“首次到访”准确。重复到访可显示为城市内的多次记录；多个景点确认不直接计为多次独立旅行。城市边界点亮表达存在到访记录，不表示整个行政区都走过。

## 短暂弧线的采纳规则

- 触发：打开已有明确城市顺序的跨城旅程，或主动进入年度回顾时播放；地图首页可后续提供一次轻量开场，但不把它放在核心浏览路径之前。
- 时长：建议整个入场约 1～1.5 秒，最长不超过 2 秒；仅少量线条逐步出现、淡出，不叠加大幅相机飞行和持续闪烁。
- 数据：只连接已知行程中的明确城市顺序；年度记录仅有地点集合而没有明确行程关联时，保持城市点亮，不自动生成往返、家乡出发或航班关系。
- 含义：表达“去过这些地方”的旅行意象。没有真实交通方式时不显示飞机或航班标签，不加入真实轨迹图层，也不计入里程、不导出为 GPX。
- 打断：用户开始拖动、缩放或点选时立即退场；同一回顾场景不反复播放，减少动态效果偏好下静态呈现即可。

## 路线与图文的联动

地图叠加可借鉴“主线清楚、背景安静”：点击一条路线卡只突出当前路径，其余降透明度；点击地图路径反向定位记录卡，保留当前年份和地区。路径与圆点优先，名称按空间渐进显示，沿用此次固定锚点／实际尺寸避让修正。

路线卡先用已有几何绘制轻量 SVG 轮廓，保留多段之间的断开，不为缩略图强行连接。默认可用暖色纸面代替再请求一张在线底图；是否需要带底图的缩略图后续再验证。已保存几何、路线来源及现有可用里程优先复用，不因截图中有数据就新增持续 GPS 采集。

里程需要区分 GPS 实录、导入参考、路网规划和手工补绘；规划线不能汇总成“真实走过”，混合交通不能汇总成徒步里程。截图可见多色路线，但不能仅凭图片断定其着色规则。若以后按速度着色，需要实际时间／速度样本，不能依据线形或距离编造。

## 建议暂不照搬

深色霓虹、发光边框和大块时间尺不直接替代现有暖白视觉；“城市／角落／地点”等分类也不照搬成一排新底部入口。我们继续围绕城市、旅程和图文建立结构，有明确数据与用途时再加入细分维度。

“探索面积”、全球百分位、自动到访和持续运动记录暂不采用；本项目已有用户明确的手动确认与回程补记习惯。照片与轨迹卡可借鉴信息组织，自有图标与色板继续统一。

## 建议实施顺序与验收

1. 先完善城市图的视觉层次、展开抽屉的城市照片卡，以及卡片／地图双向联动。收起仍仅留原单行，不增加常驻卡片区。
2. 再补路线缩略卡、选中高亮及紧凑年份浏览；卡片与地图使用一致的筛选条件。
3. 最后加入可中断的短暂城市弧线与年度回顾，沿用减少动态效果偏好。

实际实施后继续两轮自审：第一轮重点看城市点线密集程度、封面归属、抽屉收起／展开和地图留白；第二轮复看窄屏／横屏／桌面、年份切换、卡片联动和动画中断。验证实际来源标签、空数据与日期缺失，不以演示截图代替真实数据流程。

参考分析阶段：第一轮逐图提取可见结构并对照现有需求；第二轮结合用户对弧线的纠正，复核哪些只是静态截图推测、哪些可能误导路线和照片来源。当时仅整理建议；下文另记本次实现、两轮页面自审及验证结果。

## 本次实现与数据边界

- 城市列表改成照片卡，单卡铺满、多个城市双列。提供最早／最近记录、到访数、关联旅程和图文数量；封面统一标记“相关旅程封面”，图片加载失败显示占位。照片按同一年份的日记、当前用户及 ready 媒体筛选；首末日期和计数独立于详情分页，不推断人生首次到访。
- 城市级底图采用高德官方 `amap://styles/whitesmoke`，保留区域、道路和兴趣点以供定位，减少建筑物层；选中路径保留森林绿与浅色轮廓，其余路径降透明度。原 SDK 自动兼容降级保留，没有在应用中强制软件 WebGL。
- 点城市卡进入城市地图；路线卡点选后收起抽屉、定位并高亮对应路径，地图点路径则展开对应卡片；到访记录与圆点同样双向联动。“查看全部”清除高亮。原 56px 单行收起状态、桌面侧栏和地图工具保留。
- 路线卡使用本地 SVG 绘制已保存几何，独立分段保持断开，显示原始资产里程、日期、方式、来源和进入行程／图文的入口；不为缩略图请求额外底图，不合计成 GPS 实录。
- “时光”浮层增加紧凑年份按钮，保留原生下拉以支持键盘和较多年份；当前年份显示在地图标题旁。年度回顾共用现有地图和抽屉，提供城市／到访统计及该年城市卡。
- 年度回顾入场按实际行程的日／地点顺序连接已确认的相邻城市，最多 3 条弧线，约 1.65 秒后移除；缺确认或中心点会断开，不跨独立旅程推断关系。拖动、缩放、点选时立即退出；减少动态偏好下不播放。只表达回忆，不产生交通方式、里程、路径资产或 GPX。
- API 仅扩展现有只读响应，新增照片汇总和明确城市关联；没有数据库迁移。市级路径元数据从已有地点、段和几何资产读取，抽样显示不会改变原资产里程。

## 本次两轮页面自审

第一轮使用真实 HTTPS API 与真实高德 SDK，核对收起地图、展开城市卡、路线卡、年份浮层和年度卡片。发现单城市半列留白较多、城市详情仍可能混入其他年份的日记，分别改为单卡铺满和服务端日记年份筛选；同时修正城市标记文字的尺寸／图标原点和强制显示绕过避让的问题。

第一轮还发现 SDK 虽返回已设置浅色主题，截图仍是标准彩色图。结合高德官方说明和 SDK 检测，确认本机无头 Chromium 默认软件图形被识别为不满足矢量性能条件，自动降级栅格，此时主题不生效。在验证上下文单独开启软件 WebGL 后完成真实矢量样式截图；该测试设置未加入应用。依据：[官方地图样式](https://lbs.amap.com/api/javascript-api-v2/guide/map/map-style)、[矢量／栅格降级说明](https://developer.amap.com/faq/js-api/map-js-api/create-project/1060847223)，2026-10-23 核查。

第二轮检查 393×775、320×640、844×393 横屏及 1280×900 桌面的卡片与抽屉，以及真实市级点线、高亮、年份和回顾。进一步发现底部文字换行导致尺寸变化时，旧适配会覆盖选中的相机；改为尺寸变化保留选中对象，并增加专项验证。相关截图和后续复看在本机 `data/footprint-refresh/`，测试场景包含 `round1`、`round2-vector`、`round2-verified`；最终在 `round2-clean` 以未包装 SDK 复验，选中路径与点的目标缩放均可到 15 级；另在 `camera-check` 用临时采样确认目标相机。矢量软件渲染的过渡可能较慢，截图等待相机稳定，不据此作手机帧率承诺。

当前正式预览的两条行程均在同一城市，年度回顾不会为它们编造跨城弧线。跨城顺序、两秒退场、交互打断和减少动态偏好在隔离数据中验证，截图仅本机保存。
