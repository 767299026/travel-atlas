# 地图与路径生成方案

更新：2026-10-22。状态：**M3.1 已接入地图选点、手工几何和 GPX；自动算路仍是候选验证**。本机与现有域名上下文的真实 SDK／安全代理／显示转换已通，实际操作与限制见 [M3 记录](m3-maps.md)。早期山路样本的终点偏移、目标线路正确性、完整覆盖及供应商长期使用范围仍待验证；旧样本见 [验证计划第 6–7 节](validation-plan.md#7-浏览器地图与山路样本初测)，本节点见第 17 节。

## 1. 需要解决的不同问题

| 能力 | 项目目标 | 边界 |
| --- | --- | --- |
| 足迹总览 | 点亮国家／省市、年份筛选、城市回忆 | 不负责精确导航 |
| 详细地图 | 道路、地点、入口、选点、路线编辑 | 使用实际地图服务 |
| 地点匹配 | 将思源地名、输入和照片位置关联为地点 | 区分景区中心、入口、停车场与山峰 |
| 路径规划 | 连接明确的起终点与途经点 | 路网可能缺失或产生不符合预期的结果 |
| 实际记录 | 整理真实到访与走法 | 规划、补绘与 GPS 实录分别标识 |
| 文件互通 | GPX／GeoJSON 导入导出 | 坐标、断段、来源与使用授权须明确 |
| 高程与统计 | 海拔、里程、爬升和预估耗时 | 数据来源、精度和估算口径独立记录 |

已确认不需要离线地图，不以持续后台定位为核心流程。地图展示可行不代表目标山路自动规划已经可用。

## 2. 两种地图界面

足迹首页延续原型的矢量行政区图、统计和标记，保留图鉴风格；需要核对原始边界数据及使用条件。详细规划使用地图 SDK，业务面板、照片和地点列表沿用品牌，但不能承诺第三方底图可以无限自定义或删除其标识。

二者共享目的地、行程及确认到访数据。计划中的地点和心愿不点亮实际足迹，完成状态也不自动等于实际到访。

## 3. 供应商候选

| 方案 | 适用方向 | 取舍与状态 |
| --- | --- | --- |
| 高德 JS API + WebService | 国内底图、POI、驾车及步行等规划 | 首个验证对象；覆盖、保存与导出授权待核对 |
| 腾讯地图 + WebService | 国内地图、搜索与多种路线 | 主要备选，需要同样样本测试 |
| 百度地图 | 国内地图、地点和规划 | 可行备选，单独处理坐标、配额及权限 |
| 天地图 | 底图和地理信息候选 | 本轮文档读取未完成，不能据此确认细节能力 |
| MapLibre／Leaflet + 外部底图及路由 | 自定义样式、专题图层和轨迹展示 | 渲染、底图、搜索和路由分别选择，运维与授权工作更多 |
| 自建底图、搜索及路由 | 掌握数据和计算过程 | 后置，先证明区域需求和资源可承受 |

高德、腾讯和百度官方资料列出正式规划接口；这些能力不能替代国内指定山路的覆盖测试。MapLibre 是渲染引擎，不附带完整底图、POI 与路由。OSM 数据和公共瓦片服务是不同层次，不能把公共服务当作无限量保障。

参考：[高德规划](https://lbs.amap.com/api/webservice/guide/api/newroute)、[腾讯官方接口说明](https://github.com/TencentLBS/tencentmap-webservice-skill)、[百度规划](https://lbsyun.baidu.com/docs/webapi?title=directionlite%2Fguide%2Fwebservice-lwrouteplanapi)、[MapLibre](https://maplibre.org/maplibre-gl-js/docs/)、[OSM 瓦片政策](https://operations.osmfoundation.org/policies/tiles/)。

社区户外方向已补充 [OSM／OCM 与户外数据源调查](community-outdoor-maps.md)：OSM 是原始社区数据，OpenCycleMap 偏骑行，OpenHikingMap／OpenTopoMap 是底图候选，Waymarked Trails 用于查看已标记线路，自动算路另行选择。建议继续评估独立的户外查看模式；国内覆盖与访问速度尚未实测，不因此替换或锁定主供应商。

### 3.1 高德验证的账号与 Key 准备

2026-10-21 核对官方流程。当前个人项目建议注册高德开放平台开发者账号并完成个人实名认证，先开展技术验证；实际服务权限和额度以账号控制台为准。此准备不代表已最终选定高德或获得额外数据使用授权。

在控制台“应用管理”创建“迹屿 Travel Atlas”应用，分别添加：

| 平台类型 | 用途 | 建议环境变量 |
| --- | --- | --- |
| Web端（JS API） | 浏览器地图展示与交互 | `AMAP_JS_KEY` |
| 对应 JS API 安全密钥 | 配合 JS Key 使用；正式接入优先按官方方式放服务端代理 | `AMAP_JS_SECURITY_CODE` |
| Web服务 | 后端地点搜索、坐标与路线相关 API | `AMAP_WEB_SERVICE_KEY` |

JS Key 与 Web服务 Key 不混用。后两项敏感值只放项目私密 `.env`，不写文档真实示例或前端公开变量。浏览器 JS Key 按后台提供的来源限制配置。暂不需要 Android 原生 SDK Key，后续根据客户端实际接入方式决定。

注册和创建由用户在自己的账号完成。用户随后已填写上述三项配置；本机检查 `.env` 权限和 Git 忽略正常，已完成 WebService 小范围调用，以及回环地址上的 JS 地图加载、安全代理和 JS 搜索。生产域名的来源限制与鉴权仍需单独验证。

参考：[创建 Web服务 Key](https://lbs.amap.com/api/webservice/create-project-and-key)、[JS API 准备](https://lbs.amap.com/api/javascript-api-v2/prerequisites)、[JS 安全密钥](https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode)、[账号权益与计费](https://lbs.amap.com/pages/base_service_price)。

## 4. 混合分段生成

一次行程中可以采用：酒店到入口由驾车服务规划；入口到山顶用步行规划或参考轨迹；缺失路段人工补绘；城市间交通填写接驳安排，不强行生成徒步连线。

| 来源 | 可实现内容 | 要保留的限制 |
| --- | --- | --- |
| 国内自动算路 | 在服务已覆盖路网上连接节点 | 失败、绕路或不符预期时反馈用户，不自动伪装成功 |
| OSM 徒步路由 | 用已有路网及徒步配置生成路径 | 当地数据完整性、网络及授权须验证 |
| 参考 GPX | 展示、复用、编辑已有轨迹 | 记录作者、时间、使用范围；不自动当作个人实录 |
| 手工补绘 | 地图点选或绘制线路 | 人工记录／示意，不能标为 GPS 实录 |
| 照片 GPS／时间 | 提供途经点、拍照顺序及日记关联 | 不恢复照片间唯一真实路径；照片可能无 EXIF |
| 思源／AI 提取 | 路线名称、地名、访问顺序和参考信息 | 位置和路径几何需要另行确认 |

默认优先复用已确认的自有资料或轨迹，合适路段调用规划；未知段保留待处理或明显的示意线。是否切换到另一供应商不能只看接口报错，还需考虑坐标、数据使用与展示约束。

OSM 引擎候选：BRouter、GraphHopper、openrouteservice；OSRM 也支持 foot 配置。候选不是全部安装，需按同一国内样本比较。BRouter 的 trekking 配置偏自行车，徒步应评估明确的 hiking 配置，不能因名称含 trekking 就当成山地徒步。

参考：[BRouter](https://github.com/abrensch/brouter)、[山地徒步配置](https://github.com/abrensch/brouter/blob/master/misc/profiles2/hiking-mountain.brf)、[GraphHopper](https://github.com/graphhopper/graphhopper)、[openrouteservice](https://giscience.github.io/openrouteservice/run-instance/)、[OSRM profiles](https://project-osrm.org/docs/v6.0.0/api/profiles.html)。

## 5. 坐标与业务格式

GPS／GPX 常用 WGS84，高德使用 GCJ-02，百度还涉及 BD-09。内部统一经度在前、纬度在后的业务接口约定；供应商请求参数顺序由适配器处理，不能直接拼接混用。

每份几何保留原始坐标、坐标系、来源及转换记录。只在确认转换过程、精度和适用范围后生成展示或导出版本，不反复覆盖原始点。

GPX 与标准 RFC 7946 GeoJSON 都约定 WGS84。GCJ-02 点串可作为带明确坐标系的内部几何 JSON 保存，但不能原样标记为标准 WGS84 GeoJSON／GPX。供应商返回数据本身是否允许保存和转换，仍需核对使用范围。

参考：[高德坐标说明](https://lbs.amap.com/api/javascript-api/guide/transform/convertfrom)、[GPX 1.1](https://www.topografix.com/gpx/1/1/)、[GeoJSON RFC 7946](https://datatracker.ietf.org/doc/html/rfc7946)。

## 6. 地点、路段与版本字段建议

| 范围 | 建议字段 |
| --- | --- |
| 地点 | 业务 ID、名称／别名、所属地区、POI ID 与供应商、对象类型、坐标及坐标系、来源、匹配／确认状态 |
| 路段 | 起终点、所属行程／日期、交通方式、几何来源、原始几何、计划或实际、生成时间、版本、确认状态 |
| 来源与使用 | GPS 实录／导入参考／路网规划／补绘、源文件／服务、允许使用范围、必要时间戳 |
| 统计 | 来源提供值或自己的计算值、估算／实测标记、算法及数据版本、缺失状态 |

“实际记录”的含义是用户整理的真实行程，不保证其中每段都是 GPS 实测；仍需要保留来源标签。计划和实际使用独立记录，复制时生成独立标识，保留复制关系。编辑某个节点只重新计算受影响的相邻路段，保留用户已确认的其他路段。

上述字段已形成 [路线模型 v0.1](route-domain-model.md) 及 [路线接口草案](route-api-contract.md)，进一步区分几何有效性、用户核对、任务状态及来源权限，定义跨日缺口、版本冲突和候选采纳。它们是实施建议，尚未成为正式数据库或 API。

## 7. 统计与高程

- 多段轨迹保留断点，不能把不连续段直接连线计入里程。
- 区分实际耗时、文件含有的时间、规划服务预估；没有时间点时不生成运动速度。
- 有海拔文件需处理异常和噪声，不能简单把所有上下波动累加为实际爬升。
- 外部 DEM 可提供高程估计，结果受分辨率与地形影响，标注为估算，列为后置能力。

2026-10-21 三个山路初测的供应商时间均近似按 1.25m/s 换算，未获得体现爬升与地形的证据。界面需标注为供应商步行估计；山地参考时长可另行填写并保留来源，不直接用于强度评级或宣称到达时间。

参考：[Open Topo Data / SRTM](https://www.opentopodata.org/datasets/srtm/)。

## 8. 配额、保存和导出是选型条件

高德公开计费页分别列出地图初始化、搜索、路线等能力；实际可用量取决于账号与产品权限，不能承诺个人使用永远免费。

其协议对缓存、下载、派生及脱离服务展示等行为有约束。长期路线档案、编辑后分享、GPX 导出、跨底图展示及截图海报等必须核对对应授权，不能仅根据技术上可取得点串就认为可无限保存和发布。

自有记录、手绘和来源允许使用的 GPX 可按各自范围处理；第三方结果及其派生版本保留来源，授权不明时不得默认为自有数据。最终以适用服务条款和获得的权限为依据，不在本文作未核实的授权结论。

参考：[高德计费](https://lbs.amap.com/pages/base_service_price)、[高德服务协议](https://lbs.amap.com/pages/terms/)、[百度权益](https://lbsyun.baidu.com/solutions/privilege)。

## 9. 当前验证边界

本机已配置地图凭据，首次 WebService 请求成功。湖畔样本在带 POI ID 与仅坐标两种模式下返回显著不同的路线及端点，细节见 [验证记录](validation-plan.md#6-高德-webservice-首次连通性验证)。实现中需要对几何首尾和用户确认位置进行检查，不能仅依赖回显的 origin／destination 或接口成功状态。

本机回环地址的 JS 地图、服务端安全代理、搜索、示意折线与手机宽度适配已通过初测。徽杭古道浙江入口至蓝天凹、黄山云谷寺至白鹅岭、长坪沟喇嘛寺保护站至木骡子均返回几何；长坪沟终点仍偏移约 837m，不能视为完整到达目标。具体条件见 [第 7 节](validation-plan.md#7-浏览器地图与山路样本初测)。

社区数据后续已完成三个区域对象检查、黄山简化图连通与 BRouter 徒步 profile 单样本。BRouter 返回约 3.12km 路径，与同一组 OSM 输入点的局部图候选基本重合，并可输出带来源的 GPX；默认 profile 和生产安排未定案，模型高程／时间非实测。证据见 [第 9–11 节](validation-plan.md#11-brouter-徒步路由单样本验证)。

尚未证明目标山路完整覆盖或人工确认的路径正确性，也未完成持久保存和导出权限确认。生产域名及安卓仍待联调；原型地点顺序线不是算路成功证据。

先测城市／湖畔、景区步道、古道、山地沟谷和混合跨城五类样本；每个结果记录入口位置、实际采用路径、失败／绕路、来源、耗时及权限状态。只有验证结果满足已约定需求时才锁定主供应商。
