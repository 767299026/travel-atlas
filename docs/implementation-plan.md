# 首版实施清单与交付顺序

版本：v0.2，2026-10-21。状态：**M0／M1 已完成本机实现与验证，M2–M5 为后续计划**。承接 [产品方案](product-plan.md)、[路线模型](route-domain-model.md)、[API 草案](route-api-contract.md) 和 OpenDesign v4；具体接口、字段仍以实施时的契约校验为准。

## 1. 第一批要交付的结果

第一个可验收版本先完成：**本人登录 → 新建行程 → 安排多日地点 → 保存到服务器 → 刷新／重新登录后恢复**。

地图服务暂不可用时也能保存文字地点和交通安排；真实轨迹、图文、分享和资料接入按下述里程碑逐步加入。此顺序不改变最终图文旅行记录的目标，也不要求先做齐全国路网或 AI。

使用端继续以 v4 交互为基线。正式实现写入本仓库前后端目录，OpenDesign 原型由用户维护；不将演示 IndexedDB、示例照片和虚构旅程直接搬成真实用户数据。

## 2. 里程碑

| 阶段 | 交付内容 | 完成依据 | 外部前置 |
| --- | --- | --- | --- |
| M0：项目基础与数据连接 | 代码组织、已确认栈、运行时契约、专用 MySQL 连接与迁移流程、配置隔离 | 服务可启动、依赖状态明确、迁移可重放，测试库与业务库边界明确 | 专用库／账号；具体 API／ORM 初选落实 |
| M1：私有行程编辑 | 单用户登录、行程列表／新建／详情、每日地点、排序／跨日移动、保存与冲突 | 刷新、重启和重登后内容存在；冲突不覆盖草稿；未登录或越权请求被拒绝 | M0；暂不依赖地图供应商 |
| M2：回程记录与图文 | 完成状态、计划复制实际、独立到访、日记正文与受控图片、最小独立管理页面 | 计划／实际独立，到访明确确认；真实照片上传／删除／访问可控，管理功能入口独立 | 手机照片样本、媒体存储与备份选择 |
| M3：地图与路线 | 国内选点、户外查看、手工补绘、已通过条件的算路候选、GPX 导入导出 | 明确 CRS 和来源；偏移／断段可见；改点后旧结果不覆盖；文件导入导出可复查 | 图源／路由接入条件、坐标转换与权限验证 |
| M4：分享与上线 | 访客视图、撤销链接、公开范围、HTTPS、部署、备份恢复 | 私密日记／图片不泄漏；撤销有效；恢复后数据可读，真实使用网络可访问 | 域名、生产服务安排、媒体存储及资源测量 |
| M5：资料与 AI | 思源原文快照／提取／审核、路线模板、条件检索，随后问答与规划草稿 | 更新不覆盖人工修订或旧行程；回答带引用，无资料时明确缺失 | 资料规则、AI 供应商及实际问题样本 |

本轮只交付网页，通过 Nginx／OpenResty 预览与访问，不要求安卓包；安卓仅保留未来扩展选项，复杂高程分析后置。M5 可以先做思源提取和基础搜索，AI 不作为前三阶段可用性的前提。M4 之前可进行私有联调，公开上线按该阶段单独安排。

## 3. M1 页面与字段映射

| 页面／组件 | 第一批真实字段与操作 | 与 v4 的对应 |
| --- | --- | --- |
| 登录 | 本人账号、密码、登录错误与会话到期 | 首次真实服务需新增入口，关闭公开注册 |
| 旅程列表 | 标题、目的地摘要、可空日期、状态、更新日期 | “计划中／已完成”列表；空库显示真实空状态 |
| 新建／基本信息 | 标题、出发地文字、多个目的地、时区、可空日期 | 保留多目的地，不恢复为单城市模型 |
| 行程详情 | 计划 route、日期切换、地点列表、交通／缺口、备注、保存状态 | 每日地点优先，路线辅助区域不伪造已算路 |
| 地点编辑 | 名称、地区、角色、选填时间、备注、可空位置 | 未定位名称可保存，明确“待定位” |
| 地点更多菜单 | 排序、首尾移动、跨日移动、删除 | 保留有文字的菜单和禁用说明 |
| 草稿与冲突 | 未保存标识、本机草稿、服务端版本、离开提示、冲突处理 | 保留 v4 的草稿流程；“已保存”依据服务端确认 |
| 我的 | 当前个人资料与退出登录 | 不混入用户、资料或供应商管理 |

出发地文字在首次计划中形成 `departure` stop；页面摘要从该节点派生。首版位置暂缺时不强制用户选地图，也不生成默认坐标。计划日期可以未定，不以当天日期伪装用户已选出发日。

地图／回忆等导航的完整外观可随使用端迁移，但未实现功能必须明确可用状态，不保留能被误认为真实服务的分享、AI 或示例数据。

## 4. M1 最小接口与表

### 接口清单

| 接口建议 | 用途与依赖 |
| --- | --- |
| `GET /health` | 进程基础状态；不暴露配置或数据库异常正文 |
| `POST /api/v1/auth/login` | 校验已初始化的本人账号，创建服务端会话 |
| `GET /api/v1/auth/session` | 当前本人及必要权限摘要 |
| `POST /api/v1/auth/logout` | 撤销当前会话 |
| `GET /api/v1/journeys` | 当前用户列表，使用分页／游标 |
| `POST /api/v1/journeys` | 原子创建行程及空计划 route |
| `GET /api/v1/journeys/{journeyId}` | 本人行程及当前 route 引用 |
| `PATCH /api/v1/journeys/{journeyId}` | 版本化修改标题、目的地摘要等元数据；出发地通过路线命令修改 |
| `GET /api/v1/routes/{routeId}` | 读取日期、地点、连接、版本及保存摘要 |
| `POST /api/v1/routes/{routeId}/commands` | 日期／地点编辑、排序、移动、连接方式、备注及原子保存 |

本人账号通过受控初始化流程创建，密码只保存哈希，不提供公开注册。会话落库、撤销与接口校验从第一批建立；独立管理端的账号管理随 M2 加入，不放到使用端导航中。

### 表与迁移分批

| 迁移组 | 表建议 | 首批目的 |
| --- | --- | --- |
| 0001：身份 | `users`、`sessions` | 本人身份、必要角色与可撤销会话 |
| 0002：路线编辑 | `journeys`、`journey_routes`、`route_days`、`route_stops`、`route_segments` | 保存行程、多日、多地点与交通／缺口，建立 owner 与外键约束 |
| 0003：版本保存 | `route_revisions`、`idempotency_records` | 回查、冲突和网络重试；不把原始媒体或几何全文重复放入快照 |

先实现 M1 所需的命令子集，复制实际、自动算路、媒体和共享不以空接口伪装完成。`geometry_assets` 随补绘／导入加入，`routing_jobs/routing_candidates` 随自动算路加入，其余表与功能同步引入。

表名是当前建议，与最终 ORM／迁移工具一起落实。每个迁移先在隔离环境执行；本机当前使用专用库内随机前缀测试表，原因与清理边界见 [开发说明](development.md)。需要修改已有业务数据的操作先备份并提供可复查迁移，不用“清库重建”代替升级。

## 5. M1 验收场景

| 编号 | 操作 | 应观察的结果 |
| --- | --- | --- |
| A1 | 空库登录、新建两个目的地的行程 | 产生本人行程和计划 route，真实空列表无示例旅行 |
| A2 | 不选地图，保存未定位地名、时间和备注 | 成功保存且仍显示待定位，不出现假点或路线 |
| A3 | 新建两天，添加重复酒店与景点，排序和跨日移动 | 各 stop 保持独立，变化的连接正确，其他地点不丢失 |
| A4 | 保存后刷新、退出重登并重启 API | 服务端已确认内容恢复，本机草稿与服务器内容可区分 |
| A5 | 两个浏览器分别编辑同一 route 版本 | 后保存者收到 409，保留草稿，不静默覆盖 |
| A6 | 重发同一个保存请求 | 相同幂等 ID 不产生重复地点；同 ID 不同内容可识别冲突 |
| A7 | 一条命令中引用不存在或不属于该 route 的地点 | 整批事务失败，不留下半套日期或连接 |
| A8 | 未登录／会话撤销后请求私有数据；隔离测试中尝试另一用户对象 | 服务端拒绝访问，不靠按钮隐藏；测试账号不对外开放注册 |
| A9 | 暂停数据库或模拟网络保存失败 | 不显示虚假的“已保存”，草稿可保留，错误不含凭据 |
| A10 | 320px 窄屏、长地名、表单末尾与离开编辑 | 保存入口可达、无横向溢出、草稿提示可操作；真机键盘另验 |

A1–A10 已按本轮后端集成与桌面／手机尺寸浏览器测试验证；A9 用关闭独立测试连接池与浏览器断网模拟，未停止共享 MySQL；真机键盘另验。结果见 [开发记录](development.md)。按实际失败风险补充测试，满足本阶段后进入下一阶段，不为 M1 提前实现全部地图服务或复杂队列。

## 6. 开发组织建议

前后端继续在本仓库。实际开始实现时建议使用端与管理端分别构建，共用类型契约与样式基础；后端保持单服务模块化组织。最终目录与包管理器在建立代码骨架时确定，不把本稿示意路径当作当前文件已存在。

建议先落实已有 Fastify／运行时 Schema／Drizzle 初选的兼容组合，锁定版本，再生成接口契约。MySQL、OpenResty 复用现有服务；首批不要求新增 Redis、Qdrant、本地 AI 或全国地图数据库。

私密 `.env` 只供对应服务读取，前端仅得到必要公开配置。使用端与管理端分别打包，生产按需提供静态资源，API 单独运行；本机临时验证不等于公开部署。

### 网页预览方式

2026-10-21 用户明确当前不需要安卓包。开发调试可使用 Vite 开发服务器；可供 Nginx／OpenResty 托管的预览采用网页构建，通常由 `npm run build` 生成 `dist`（最终以项目脚本与输出配置为准）。电脑和手机均通过网站地址访问，无需安装 APK。

Nginx／OpenResty 提供网页静态文件，`/api` 等独立路径转发到 Node 后端，后端再访问 MySQL。采用 Vue Router history 模式时配置页面回退，同时确保 API 请求独立处理，避免 API 错误被回退成 HTML。管理端独立构建并使用自己的入口。

参考：[Vite 静态部署](https://vite.dev/guide/static-deploy.html)、[Vue Router history 与 Nginx 配置](https://router.vuejs.org/guide/essentials/history-mode.html)。当前已提供构建产物与本机回环预览，未修改实际 Nginx 配置或公开发布站点。
