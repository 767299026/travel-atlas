# 手机地图布局与渲染替换

日期：2026-10-23。用户在小米 14 浏览器反馈：标题／区域名称、统计／图源说明重叠，三个地图按钮叠框，默认视野偏小；拖动缩放有明显低帧感。随后要求优先采用社区成熟方案。

## 选型结论

全国、省级和世界图鉴改用 **已有的 Leaflet 1.9.4 + Canvas GeoJSON**，替换 Vue 自绘 SVG 投影和逐点拖动逻辑。市级继续高德 2D；图鉴继续读取原 DataV／Natural Earth 参考数据，不请求新的公共底图瓦片。

| 方案 | 官方能力 | 本次判断 |
| --- | --- | --- |
| Leaflet + Canvas | GeoJSON、Canvas renderer、拖动惯性、触摸缩放、滚轮、键盘 | 已有依赖、原生地图交互，本轮实际替换并测量 |
| MapLibre GL JS | WebGL 地图、GeoJSON source/layer、GPU 绘制 | 可继续作为大量数据／GL 场景候选；本轮未安装、未与 Leaflet 做同机直接比较 |
| Apache ECharts | 地图可视化，Canvas／SVG 渲染器 | 适合统计图表；当前业务包含地图交互和足迹，采用已经使用的地图库 |

2026-10-23 核对官方资料：[Leaflet 参考](https://leafletjs.com/reference.html)、[GeoJSON 示例](https://leafletjs.com/examples/geojson/)、[MapLibre GL JS](https://maplibre.org/projects/gl-js/)、[ECharts 渲染器说明](https://echarts.apache.org/handbook/en/best-practices/canvas-vs-svg/)。并检查本机 Leaflet Canvas／TouchZoom 源码中的重绘调度，版本保持现有 1.9.4，没有增加 npm 依赖。

地图首次访问会按需加载既有 Leaflet chunk（约 148.62kB，gzip 43.34kB），此后与户外查看页复用。省市／世界几何仍由鉴权 API 按需获取。依赖体积与交互响应分别衡量，不宣称首次网络请求为零成本。

## 原因与处理

旧组件在每次指针移动后重新计算投影、遍历边界顶点、生成 SVG `path.d` 字符串并更新 DOM。大块边界数据带来主线程长任务，根因超出单纯布局错位。

新组件把几何交给 Leaflet Canvas。拖动、惯性、缩放动画、双指手势与坐标换算由成熟组件负责；Vue 不逐帧重建几何。文字避让只在交互结束、数据或尺寸变化后执行。Canvas 图形、DOM 地点标记、地区列表和键盘入口共同提供交互；名称全部按纯文本创建，区域点亮、年份、心愿和归属规则保持原数据契约。

默认国内视野聚焦主要陆地区域并适度放大、居中；“查看全貌”恢复完整数据范围。此操作仅调整相机，保留全部原始地图几何。省级按容器适配；用户手动操作后的普通尺寸变化保留视野，重置按钮回到适配视野。

## 布局修正

- 标题、地图视口、图源说明、统计工具栏、城市抽屉分配独立网格行，不再用固定 bottom 值将这些区域互相叠放。
- 地图工具栏三枚按钮各 44×44 CSS 像素，取消 Android 原生 appearance、子按钮圆角和阴影；外框统一圆角，分隔线统一绘制。
- 武汉等已有足迹标记的地区不再同时显示第二份同名区域标签；其他名称与地点标签避让，放大后可出现更多名称。
- 市级图层开关、未定位说明和可展开的路径来源说明放在地图下方，避免遮住道路与标记；相机留白按真实地图视口尺寸计算。
- 小屏与浏览器工具栏占用较多高度时压缩折叠抽屉并隐藏重复的页头；保留主导航、地图标题和操作。`100vh` 回退至 `100dvh`；设置文本自动调整口径，保留浏览器页面缩放能力。
- 桌面侧栏保持独立，不覆盖地图。截图只用于本机核对，用户上传的 `tmp/` 目录已排除 Git。

## 性能测量

环境：本机无头 Chromium，393×775 CSS 视口，4 倍 CPU 降速；每张地图输入 240 次鼠标移动。数据相同、浏览器及视口相同，组件与布局已更新。旧版取替换前已部署构建；不拿原型示意图当测量对象。

| 指标 | 全国旧 SVG | 全国 Leaflet Canvas | 湖北旧 SVG | 湖北 Leaflet Canvas |
| --- | ---: | ---: | ---: | ---: |
| 路径属性更新 | 8365 | 0 | 4063 | 0 |
| 长任务数（>50ms） | 239 | 0 | 239 | 0 |
| 采样帧间隔 P95 | 416.7ms | 16.8ms | 116.6ms | 16.8ms |
| 采样期间主线程任务时间 | 92651ms | 1611ms | 26173ms | 1414ms |

世界图新版本也通过同样输入检查：路径属性更新 0、长任务 0、P95 16.7ms，主线程任务时间 1569ms。原始结果在忽略的 `data/map-performance/`：`before.json`、`leaflet-canvas.json`、`leaflet-canvas-final.json`。最后一次采样增加输入结束后 100ms 收尾，涵盖拖动结束后的重绘；前两次没有该收尾，不能将三份数据视作完全相同的重复试验。

上述结果用于定位并消除旧实现的主线程瓶颈，**不是小米 14 真机帧率，也不是 120Hz 达标证明**。实际手机刷新率、浏览器调度、GPU 和省电设置仍需真机复核。没有单凭“Canvas”或“WebGL”名称宣称必然流畅。

## 验证与交付

- `npm run test:browser:mobile`：15 组，393×775／660／844、360×740、320×640、393×560，检查标题／地图／说明／统计／抽屉／导航不相交、无横向溢出、三控件的尺寸与点击命中、触摸放大缩小、原生单指拖动／双指缩放、城市布局与桌面侧栏。尺寸根据截图估算，属于 Android Chromium 触摸模拟。
- `npm run test:browser:atlas`：13 组既有地图、城市记录、图层、年份、归属、失败恢复和模拟清理流程回归通过。原 SVG 选择器改为组件公开语义与 Canvas 状态，继续验证实际业务操作。
- `npm run test:browser:pages`：原型页面 16 组回归；构建含 Vue／TypeScript 检查。
- `scripts/browser-map-performance.ts`：支持 `PERF_LABEL`、`PERF_SCOPES`、`EXPECT_STATIC_PATHS`；性能不是与产品镜像的单元断言，保留真实拖动与浏览器主线程测量。
- 现有 screen 主站已按暂存构建切换，旧构建／哈希资源保留。真实域名 9 组核对通过（图鉴／世界、滚轮、市级高德、记录与图文等，无 pageerror），结果记录在 `data/atlas-review/mobile-layout/`。API、数据库和现有模拟数据不迁移、不重置。

未覆盖：小米硬件实际高刷、真实手机浏览器版本／省电模式、真机外网速度。其余长期运行与恢复范围继续引用已有文档。
