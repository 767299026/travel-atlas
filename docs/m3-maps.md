# M3 地图与路线

更新：2026-10-22。状态：**M3.1 本机实现、隔离验证与预览升级完成；M3.2 后续推进**。承接 M2，继续保留 OpenDesign 原工程只读、screen 预览与节点完成后推送 GitHub 的约定。

## 节点拆分

1. **M3.1 地图、手工路径与 GPX**：独立路线地图页，国内高德底图与选点；坐标来源；独立不可变几何资产；手工补绘／分段；GPX 解析预览、确认绑定、原文件保存、WGS84 导出；过期、核对、保护和用户归属。
2. **M3.2 算路候选**：满足供应商使用条件后接入路由；外部请求不占数据库事务，结果先预览并核对端点、版本和输入，再主动采纳。独立户外底图与 BRouter 等按验证结果推进。

M3.1 不把参考 GPX、补绘或实际记录标为 GPS 实录，不自动确认到访，不将未定位点补成直线轨迹。地图加载失败时，文字编辑与文件处理仍可使用。

## 实现边界

- 高德 JS Key 是浏览器运行时加载所需的公开标识；安全密钥、WebService Key 仅服务端使用。采用官方 `/_AMapService` 安全代理，固定上游、限定路径、鉴权与限流，不提供任意 URL 代理。
- 高德选点与补绘保留 GCJ-02；导入 GPX 保留 WGS84 原件。WGS84 仅经官方转换生成临时高德显示坐标，不覆盖原件，不做未经核实的反向转换。
- 导出要求 WGS84、当前有效且经用户核对、来源使用范围允许；GCJ-02 补绘和供应商来源未核实的导出受阻。部分缺段需先展示范围并明确确认。
- 原始 GPX 只在用户确认保存后持久化，作为本人私有资产；多段不跨缺口连接计程，不从时间／高程推断实录归属，不伪造缺失采样。
- 复制计划至实际继续清空几何绑定，保留地点坐标与复制来源；以后按资产策略建设几何复用，不冒充已完成。
- 先隔离迁移与 API／浏览器验证，再数据库备份、增量迁移、切换预览构建；不把本机成功等同真实手机、地图账号授权或正式上线验收。

## 使用方式

1. 行程详情点击「查看路线地图与 GPX」，计划和实际分别进入自己的地图页。
2. 在「地点位置」选择地点，可填写经纬度及原始坐标系，或点击「加载高德在线地图」后选点。位置先加入行程修改，再点「保存行程修改」。更换坐标会使相关旧路径过期。
3. 在「地点之间的路径」选择连接，先明确交通方式并保存；接驳缺口不会自动变成徒步路径。所有连接按行程地点顺序读取、展示和导出，不依赖数据库返回顺序。
4. 「手工补绘这段」支持高德 GCJ-02 地图点击，或填写自有 WGS84 坐标；可以撤回最后一点、从缺口后另起一段。坐标系在开始时选定，已有点不会被直接重标为另一坐标系。
5. 「导入 GPX 到这段」先解析预览，填写来源、确认有权保存和导出，再保存路径。原始 XML、点串及有效的文件海拔／时间采样私密入库；状态始终为“导入参考”，不因 actual 层或带时间就标成 GPS 实录。
6. 保存路径后查看来源、端点诊断，再点「已核对这段路径」并保存行程。可保护路径，保护状态下替换／移除被拒绝；解除保护并保存后再操作。移除绑定保留历史资产，不自动删除到访／日记。
7. 导出前预览覆盖范围。当前路径必须有效、已核对且为允许导出的 WGS84；缺失路径或接驳缺口需要明确确认部分导出。独立段输出为独立 `trkseg`，不连接计程。

底图按需加载，进入地图页不会立即请求高德。加载后会向高德发送显示所需坐标；WGS84／BD-09 通过官方接口转换成临时显示坐标，原数据不变。SDK 会改写传入数组，调用前已复制，测试包含该行为。长路径只在在线显示时抽样，原件、存储、线长与 GPX 导出保持全部点；没有底图时仍可查看路径示意、填写坐标和处理文件。当前没有 POI 搜索、在线路由、卫星／等高线／社区户外图层。

## 数据与限制

新增 `geometry_assets`：归属用户与路线、来源类型／说明、原始 CRS 与分段、采样、点数、二维线长、导出策略、原文件／校验值、诊断和创建时间。资产不可变，保存新路径生成新 ID；route revision 只引用资产，不重复嵌入点串。改点／交通造成 stale，不能直接通过核对跳过重新整理。

| 项目 | 当前限制 |
| --- | --- |
| 几何 | 每资产最多 10000 点、100 段，每段至少 2 点；无伪造连线 |
| GPX | UTF-8、最多 1MiB；GPX 1.0／1.1 正确命名空间；支持轨迹或路线，混有两类时要求拆分，避免重复计程 |
| 解析 | 拒绝 DTD／实体声明、坏 XML、无效／越界坐标和坏采样；独立航点不转成路径，原文件保留；未做完整 XSD 验证 |
| 个人历史配额 | 200000 点、500 资产、原 GPX 合计 20MiB；包括旧资产，达到上限明确拒绝；当前没有自助历史清理／恢复 UI |
| 路段诊断 | 同 CRS 端点距离超过 150m 提醒；跨 CRS 或缺少位置明确未比较，多段提醒缺口；150m 仅提示阈值，不是安全／通行标准 |
| 里程 | 各段二维球面线长相加，不包含段间缺口；无地形长度、模型爬升、运动时间或导航安全承诺 |
| 保存与并发 | 路线版本、预期绑定与幂等 ID；锁定路径拒绝替换；不进行静默合并或后台覆盖 |
| 草稿 | 按用户／路线／标签页保存在 localStorage，含路径点或 GPX 文本；刷新恢复并保留重试标识，清理浏览器数据会丢失 |

GPX 按标准解释为 WGS84，不能自动识别来源文件是否错误标了坐标系。用户确认来源是导入前提，不是平台替外部数据赋予许可。GCJ-02 补绘的导出策略固定为 `unverified`，前端不能提交“允许导出”绕过；当前不实现 GCJ-02 → WGS84 反向转换，也不把供应商生成数据的使用条件推广到所有用途。

## 当前接口

均在 `/api/v1` 下，要求登录；写操作使用 Origin／CSRF。权属、版本、保护和策略由后端验证。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /maps/capabilities` | 运行时 JS Key／代理路径及限制，不含安全密钥或 WebService Key |
| `GET /maps/_AMapService/*` | 官方 JS 服务代理；固定上游、路径白名单、120 次／分钟、4 个并发、12s 超时、4MiB 响应上限 |
| `POST /geometries/gpx-preview` | 只读解析，不持久化原文件或资产，15 次／分钟 |
| `GET /routes/:id/geometries` | 当前绑定摘要，不含大点串／原 XML |
| `GET /geometries/:id` | 本人不可变资产点串、采样与来源 |
| `GET /geometries/:id/original` | 本人原始 GPX，attachment 下载，不经静态目录 |
| `PUT /routes/:id/segments/:segmentId/geometry` | 按版本／预期绑定保存补绘或 GPX；默认 JSON 小请求上限不变，该接口支持受限的大文件请求 |
| `GET /routes/:id/gpx-export-preview` | 覆盖、缺口与阻止原因 |
| `POST /routes/:id/gpx-export` | 检查版本／核对／策略／部分确认，返回 GPX 下载内容，不创建公开链接 |

已有命令接口增加 `review_segment`、`set_segment_lock` 和 `clear_segment_geometry`；地点位置新增选填来源 `manual_coordinate/amap_pick/gpx_endpoint`。当前 UI 不自动把文件端点变成地点，避免导入时覆盖已选位置。

## 验证与交付

- 三工作区类型检查／构建通过，累计 32 项后端测试通过（29 个子场景、3 个父测试）；M3 10 个子场景覆盖解析、代理、权限、并发幂等、源文件、采样往返、保护、过期、导出与复制隔离。
- M3 浏览器 10 组通过，注入专用 SDK 测试替身，不作为供应商联调证据；另通过真实高德 SDK、安全代理、WGS84 官方显示转换和标记检查，结果在忽略的 `data/browser-amap-check/`。
- M1 浏览器 10 组、M2 浏览器 12 组回归通过；桌面／320px／390px 尺寸无 pageerror。模拟缺少 `crypto.randomUUID` 的 HTTP 环境，使用 `getRandomValues` 生成请求标识，未引入弱随机回退。
- 地图页懒加载 JS 约 29.63kB（gzip 11.24kB）、CSS 3.04kB（gzip 1.06kB）；首屏 JS 及预加载共享块合计约 153.58kB，外部高德 SDK 不计入这些数字。
- 先生成权限 600 的升级前 SQL 备份，再应用 `0002_quiet_photon.sql`：14 → 15 张业务表，另有账本；保留 1 个本人账号，未创建演示旅程／媒体／几何，隔离表已清理。SQL 备份包含几何及原 GPX，照片文件仍需另备份。
- 暂存构建通过后切换三个 screen 预览会话；旧构建保留 `data/releases/`，前端保留前版带哈希资源。主站沿用现有域名和 OpenResty 反代，不修改原始 OpenDesign 或用户反代配置。
