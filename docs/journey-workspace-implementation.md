## 当前实现

### 页面与交互

旅程列表只有右上深色加号，按计划中／已完成筛选，归档位于菜单。新建只有名称／目的地输入，选择城市可生成名称，日期和天数不阻止创建。新版使用 Vue 页面 `JourneyWorkspace.vue`，地图与连续搜索分别拆为组件，保存队列独立于页面。

新建后只有待安排分组，按需增加一天；既有行程优先打开有安排的日期，避免空待安排遮住已有内容。城市心愿进入新建时继续带入名称与目的地。搜索按当前城市或全国调用真实高德 PlaceSearch，候选显示名称与地址，同名地点可辨认；选中后继续搜索，已加入可反选。未匹配或搜索失败时可先保存名称，位置待补。地图微调使用原地点附近的真实街道地图和中心标记，确认后保留搜索上下文；普通流程不出现经纬度。

支持按天清单／地图、桌面双栏、批量跨天移动、手柄拖动和文字排序、地点备注／预约时间／住宿补充、每天默认交通及单段例外。移动按待安排和原天数、原地点顺序收集后追加，目标已有地点不重复移动；移除后保留正常文档流的紧凑撤销条，按原分组与位置恢复，提示不遮地图摘要。地点详情中的输入会进入自动保存队列，关闭或转入整理操作不要求再保存整份行程。

地图复用当前 SDK 与官方显示坐标转换，保留原始坐标系。只显示本分组的地点，编号与清单顺序一致；直线只表示顺序，明确标记“非导航路线”。首次加载待地图就绪后立即适配所有地点，避免从全国范围长距离动画导致点位看似偏离；用户点击居中工具时保留 SDK 过渡。切换清单与地图保留页面内地图及清单上下文，浏览分组／模式按账号和旅程存入标签页。

### 保存与数据模型

新增迁移 `0008`，只为 `route_days` 增加 `is_unscheduled`（默认 false），为 `journeys` 增加可空 `planning_preferences`。仍是 21 张业务表，不批量重写既有路线、照片或日记。待安排复用路线地点模型，通过标记排除日数统计和路段生成，不能变成虚构线路或到访。规划偏好保存 POI 标识、城市归属、住宿补充和每日默认交通，旧记录默认为空偏好。

工作区保存整个计划布局，采用旅程与计划路线双版本校验、账号锁和事务。请求超时保留冻结请求及幂等键，重试确认后才提交后续本地修改，避免已写库但响应丢失时重复创建或误判。每批保存保留源地点／日期 ID 与复制来源；已有相邻路段的几何引用继续保留，坐标或交通变更使路径过期，涉及已保护路径的结构调整会拒绝并提示先解除保护。

本机草稿按账号／旅程隔离，失败仍可重试；并发冲突保留草稿，提供下载和重新读取。服务器成功返回才显示“已保存到服务器”。本地草稿不是跨设备同步或备份。

### 补记与删除

补记只接受主动勾选的地点，日期明确填写；临时地点可独立加入补记。服务端在实际记录中复用或新增对应地点，再确认到访和城市归属，不改原计划，不把未选择的计划自动标记已去过。此前已确认的到访保持保留，取消到访仍可从实际记录处理；勾选本轮新到访不强制写日记或上传照片。

删除必须明确确认范围，校验旅程及全部计划／实际路线版本，事务内删除旅程安排、相关到访、算路任务／候选／几何和分享链接。原日记、私有媒体和独立相册保持，日记的地点快照可显示关联已移除。该业务范围来自本轮删除提示，不执行任何正式资料的测试删除。

旧详细安排与图文入口移至 `/journeys/:id/edit`，实际记录、路线／GPX、分享、日记与管理端继续保留。普通工作区入口不要求操作专业路径工具。

### 接口

- `POST /api/v1/workspace/journeys`：轻量新建。
- `GET/PUT /api/v1/journeys/:id/workspace`：读取／自动保存布局、偏好、元信息及确认状态。
- `POST /api/v1/journeys/:id/workspace/visits`：批量主动补记。
- `DELETE /api/v1/journeys/:id`：显式确认范围及版本后删除。

继承登录、CSRF、本人归属及限流；不能通过传入别的路线 ID 覆盖其日期或地点。原有接口保持，旧端创建的行程可直接打开新版。

## 两轮实际自审

证据保存在忽略的 `data/journey-workspace-20261029/`，不提交数据库、截图、原型摄影或地图数据。

第一轮在临时 MySQL 前缀与媒体目录，以实际 Vue／API 和地图交互替身走通新建、连续加入四个地点、刷新保存、分天移动、编辑／撤销、地图、补记及删除。实际查看 393px、320px、844px 横屏和 1280px 截图。发现搜索弹层过矮、仅能容纳一个结果，以及交通入口位置与清单图标不合适，已调整为更高的搜索面板／独立滚动结果区、交通放在相邻地点之间，并补齐统一图标。地点详情编辑可即时进入保存队列。

第二轮在 HTTPS 域名上下文加载真实高德 SDK，业务 API 全部拦截至隔离服务。验证武汉三地点地图、点选摘要、桌面双栏、真实武汉搜索、上海中山公园搜索与微调；原始测试暴露首次相机仍在从全国范围动画过渡的问题，修正初次适配为立即完成，复查武汉中心约 114.336／30.557、上海微调约 121.419／31.222，城市归属正确。真实服务没有返回代理 HTTP 错误，相关步骤没有捕获脚本异常。

第二轮另复看移动、撤销、窄屏搜索、照片相册和旧 M2 日记／管理端流程。浏览器与 MySQL 验证不等于小米真机、真实键盘、复杂徒步线路或生产用户验收。
