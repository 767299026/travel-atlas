# 独立管理工作台

日期：2026-10-31。用户确认使用端当前效果可继续，开始管理端设计与实现。本轮沿用 `admin/` 独立 Vue 工程，不向主站导航加入管理功能，不修改 OpenDesign 原型。

## 设计与范围

保持迹屿暖白、森林绿与细线图标；桌面使用固定侧栏，手机使用抽屉导航。首页提供真实数字、最近整理的旅程与待补资料提示；操作集中在对应页面，不把所有管理表单堆在概览。

| 页面 | 本轮功能 | 边界 |
| --- | --- | --- |
| 概览 | 旅程、照片、存储、足迹、有效分享、最近旅程、待定位照片与待归属到访 | 查询当前数据库，不生成趋势或虚构活动 |
| 内容台账 | 旅程、照片、旅程到访、既有日记；关键词搜索、分页、资料详情 | 首版只读；行程安排、照片定位及记录编辑继续使用端 |
| 账号管理 | 创建、改名、角色、启用／停用、重置密码 | 沿用版本校验、最后管理员／当前账号保护和撤销会话；无公开注册 |
| 分享管理 | 查看归属、快照类型、到期时间与状态；确认后撤销 | 撤销记录写入审计；不提供分享凭证或代替用户发布分享 |
| 服务与接入 | 数据库本次查询结果、照片存储、高德、区域路由、分享配置 | 已配置不等于连通性或进程健康；不回显密钥或内部连接地址 |
| 操作记录 | 按时间分页与关键词查询，显示操作、执行账号与目标 | 仅覆盖已写入审计的操作，不宣称记录了所有业务修改 |

思源资料库与 AI 助手保留明确的“待接入／待建设”说明，不放空操作按钮。后续可增加原文快照、提取审核、同步任务、模型配置与带引用问答；这轮不实际读取思源或调用 AI。

内容管理后续可按真实需要增加状态筛选、照片预览、资料质量清单与受保护的修复操作；本轮不提供跨用户批量删除或直接修改经纬度的表格。

## 数字与状态口径

- 旅程包括计划中、已完成和已归档记录；列表按更新时间及 ID 稳定排序。
- 照片数与占用只统计 `ready` 媒体；包含原图和衍生图的存储，不是单张原图文件大小。未整理的上传也在台账中。
- 照片“已定位”依据独立照片记录中已确认、带坐标的 `place.position`，只有地点文字时显示“待补坐标”；不直接把原图 EXIF 或旧日记建议当成确认。隐藏照片单独标识，待补精确位置数字排除已隐藏照片。
- 旅程到访来自 `visits`；概览足迹另加 `place_records.kind=visited` 的独立城市记录，分别注明条数，不将两者相加解释为去过的城市数量。
- 待补城市表示旅程到访的 `place` 为空；算路失败数是历史失败任务记录，不代表当前服务故障。
- 有效分享需未撤销、未到期、分享签名配置仍匹配且所属账号启用。后台区分有效、到期、撤销、账号停用和签名失效。
- 待整理提示进入相应台账，目前不自动增加状态筛选；用户可查询并查看记录详情。

## 接口与权限

新增契约：`packages/contracts/src/admin.ts`。后端模块：`backend/src/admin-console.ts`，由现有管理路由注册。

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/admin/dashboard` | 聚合统计、待整理数量与最近 5 条旅程 |
| `GET /api/v1/admin/catalog/:resource?page=&q=` | journeys／photos／visits／diaries／shares，20 条每页 |
| `GET /api/v1/admin/services` | 配置摘要与本次数据库查询结果 |
| `GET /api/v1/admin/events?page=&q=` | 分页操作记录 |
| `POST /api/v1/admin/shares/:id/revoke` | `{ acknowledge: true }`，幂等撤销并只记录首次审计 |

所有接口必须登录并具有 `owner` 角色；普通 `editor` 返回 403，匿名返回 401。写请求继续校验精确 Origin 与会话 CSRF。管理者可查看各账号的台账，后台不会给普通编辑开放全局读取能力。

搜索限制为 100 字，页码限制为 1–9999；SQL 参数化且转义 `%`、`_`、`!`，按普通字符查询。资源名与参数由 TypeBox 校验，未知字段不静默忽略。列表不向浏览器输出密码哈希、会话、分享 Bearer 凭证、原图 EXIF 或 GPX 原件。

撤销分享事务按所属账号加锁，与原分享服务保持一致；再次请求不重复写审计，访客读取会立即失败。原始旅程／图文／照片保留。原账号管理、版本冲突及会话撤销机制继续使用，主站 API 的所有权检查不改变。

## 前端组织

- `admin/src/App.vue`：六个页面、登录、读取状态、搜索分页、资料详情和撤销确认。
- `admin/src/components/AccountsPanel.vue`：从旧管理页提取账号功能。
- `admin/src/components/AdminIcon.vue`：复用现有图标路径，补充管理所需线条图标。
- `admin/src/style.css`：独立样式与品牌色，不再导入使用端整份页面 CSS，避免全局按钮、body 内边距等相互影响。
- 使用 hash 保存当前模块，刷新保持页面；切换模块重置查询与分页。请求序号避免迟到响应覆盖当前页面，失败保留明确重试入口。
- 手机表格在卡片内横向滚动，页面本身不应横向溢出；账号与资料弹窗使用原生 dialog，包含 Escape、焦点恢复与请求期间禁关保护。

## 实施步骤与自审

1. 核对旧管理页、权限、数据库字段与已有产品决定，确定上述首批功能。
2. 建立增量管理 API、共享类型与独立页面；复用已验证账号操作。
3. 在随机前缀 MySQL 表和临时媒体目录验证权限、分页、分享撤销；不插入正式演示数据。
4. 第一轮实际截图发现：主站全局样式导致统计卡片横排挤压、桌面额外留边及窄屏台账溢出。移除整份使用端 CSS，改为管理端自有样式；增大表格与辅助文字，照片占用按 KB／MB 显示，避免小文件显示 0.00 MB。
5. 进一步定位手机横向溢出：表头中屏幕阅读器专用绝对定位文字未建立局部定位容器，超出滚动区后影响根视口；将表头设为相对定位，保留卡片内真实横向滚动。手机菜单同步补上关闭时 inert、展开时焦点转入、Escape 关闭与焦点返回。第二轮与最终结果见下节。
